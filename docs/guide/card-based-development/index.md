# 第四部分：独立游戏的卡片开发法

## 让创意成为一种日常工作

《独立游戏的卡片开发法：让创意成为一种日常工作》是一本面向独立游戏开发者的实践型方法论书籍，与 2D 教学、3D 教学和 Mine Beyond 开发实践并列，作为独立的写作分部持续更新。

## 项目定位

本书受到《卡片笔记写作法》（How to Take Smart Notes）的启发，尝试建立一套**可重复、可执行、可持续的游戏创作工作流程**。

“卡片”只是方法的载体。真正的核心是通过流程化、结构化的工作方法，降低创作门槛，减少对灵感和动力的依赖，帮助独立游戏开发者持续推进项目，并最终完成游戏。

希望回答的具体问题是：**一个独立开发者在普通的一天，打开电脑后，应该怎样有效地推进自己的游戏？**

## 希望解决的问题

- **游戏做不完**：拆解工作、明确完成标准、控制范围，并定期整合为可玩版本。
- **缺少动力**：降低开始工作的心理阻力，为每次开发准备清晰的小目标与下一步入口。
- **开发效率低**：减少反复决策、任务切换、过度研究和返工，积累可复用的经验。

## 核心方法

开发卡片代表一个**具有明确目标、有限范围和可验证成果的开发活动**。卡片可以包含目标、背景、行动、完成标准、范围限制和结果。

例如，将“完善战斗系统”改为“实现击毁最后一个矿石时触发整组奖励”。

初步的探索循环为：

**观察 → 提出问题 → 建立假设 → 实验验证 → 积累知识 → 产生新的问题。**

| 卡片类型 | 作用 |
| --- | --- |
| 观察卡（Observation） | 记录游戏体验、其他作品中的机制、玩家行为及值得研究的现象。 |
| 问题卡（Problem） | 明确当前游戏存在的问题或希望实现的体验。 |
| 假设卡（Hypothesis） | 提出一种可能的设计解决方案。 |
| 实验卡（Experiment） | 通过最小可玩原型、开发任务或玩家测试验证假设。 |
| 知识卡（Learning） | 记录实验结论、失败经验和可复用知识。 |

这五类卡片主要服务于探索和验证，如何连接实际制作、阶段性目标、范围管理与最终发布，仍需要实践研究。

## 日常开发工作流

1. **开始工作时**：取出事先准备好的卡片，明确这次工作的目标。
2. **开发过程中**：集中解决当前问题；新创意与新问题先记录下来。
3. **结束工作时**：检查完成标准，记录结果与未解决的问题，为下次开发准备入口。
4. **每周或每个开发周期**：整合并测试可玩版本，决定哪些功能继续、修改、推迟或放弃。

**完成卡片不等于完成游戏。真正的进展必须通过可玩的游戏版本来衡量。**

## 四条工作原则

1. 永远知道下一步做什么。
2. 每张开发卡片都有明确的完成条件。
3. 定期产出可玩的版本。
4. 允许删除功能和放弃创意。

## 实践案例：Mine Beyond

计划使用《MINE BEYOND: AI Assistant Included》作为实验项目，逐步积累真实开发素材。相关项目见 [Mine Beyond 开发实践](../mine-beyond/index.md)。

以“矿石组奖励”为例：

- **问题**：如何让清空一组矿石比单独击毁矿石更有满足感？
- **假设**：清空一组矿石时，额外掉落等量铁矿。
- **实验**：实现四块矿石组成的矿石组，在最后一块被摧毁时额外掉落四个铁矿。
- **验证**：观察玩家是否理解奖励来源，是否主动追求清空整组矿石。
- **新问题**：如何在攻击之前，让玩家意识到矿石之间的组关系及额外奖励？

计划连续使用一个月，观察是否更容易开始开发、是否减少无效工作与返工，以及游戏是否更稳定地接近可发布状态。这些是待验证的目标，并非已经取得的效果。

## 待研究的问题

- 卡片如何分类、拆解到什么规模，才能保持轻量？
- 如何区分探索性任务与确定性的制作任务？
- 如何处理难以拆解、无法预估时间的技术难题？
- 如何保持方向，同时允许实验带来意外发现？
- 如何把日常卡片与里程碑、范围控制和发布连接？
- 如何避免流程化导致更高效地增加无关功能？
- 如何衡量实际效果，而不仅仅是感觉更有条理？

## 核心主张

**你不需要每天都充满动力，也不需要每天都有好创意。你需要的是一套能够让自己持续创作，并最终完成作品的工作方法。**

**容易开始 → 持续推进 → 最终完成。**
